# Сервер MCP Dynamo

**MCP** расшифровывается как Model Context Protocol — протокол контекста модели. Это открытый стандарт, который позволяет ИИ-моделям подключаться к программному обеспечению через общий протокол. Сервер MCP предоставляет инструменты и данные программы ИИ-клиенту, чтобы он мог считывать контекст в реальном времени, выполнять действия и возвращать структурированные результаты.

**DynamoMCP** — это встроенный сервер MCP Dynamo. Он подключает Autodesk Assistant к активному сеансу Dynamo — графу, узлам, проводам и состоянию рабочего пространства, — поэтому ИИ-справка основана на том, над чем вы работаете.

Для пользователей Dynamo это означает, что инструмент Assistant может делать больше, чем просто отвечать на общие вопросы. Он может проверять открытый граф, помогать устранять неполадки с узлами и обновлять рабочую область на основе контекста реального сеанса вместо копирования и вставки вручную.

DynamoMCP доступен в Dynamo 4.2.0 или более поздней версии.

### Использование DynamoMCP

DynamoMCP используется через Autodesk Assistant — отдельной программы или интерфейса не существует. Именно в Assistant можно задавать вопросы, получать помощь по графу и позволять ИИ работать с контекстом Dynamo в реальном времени.

Место открытия Assistant зависит от того, где вы работаете.

- **Dynamo Sandbox** — инструменты DynamoMCP доступны в Autodesk Assistant в Dynamo.
- **Revit** — инструменты DynamoMCP доступны в Autodesk Assistant в Revit.

В обоих случаях вы остаетесь в текущем сеансе и используете тот же интерфейс Assistant для доступа к DynamoMCP.
### Возможности DynamoMCP

DynamoMCP предоставляет для Assistant набор **инструментов**. Каждый инструмент выполняет одну задачу в Dynamo, например чтение рабочей области, размещение узла или запуск графа. Вы никогда не вызываете эти инструменты сами. Вы описываете, что вам нужно, простым языком, а Assistant выбирает нужные инструменты.

Однако по-прежнему важно знать, что собой представляют инструменты. Assistant сообщает вам, что может сделать, и помогает сформулировать запросы, на которые может реагировать.

{% hint style="info" %}
Инструменты, имена которых начинаются с `get_`, предназначены только для чтения информации из сеанса. Любой другой инструмент может изменить граф.
{% endhint %}

#### Чтение текущего графа

Эти инструменты позволяют Assistant увидеть, над чем вы работаете, прежде чем помощник ответит или внесет изменения.

| Инструмент | Назначение |
| --- | --- |
| `get_workspace_info` | Перечисление содержимого рабочей области: узлов, проводов, групп, примечаний и сведений о рабочем пространстве. |
| `get_selection` | Отображение информации о выбранных узлах, проводах и группах. |
| `get_node_connections` | Отображение того, к чему подключен узел, порт за портом. |
| `get_node_property` | Отображение информации по таким параметрам узла, как предварительный просмотр, замораживание, закрепленный предварительный просмотр и метки. |
| `get_node_lacing` | Отображение информации о параметрах переплетения узла. |
| `get_installation_info` | Отображение версии Dynamo, основного приложения, в котором выполняется работа, и ссылки на примечания к выпуску. |

*Пример запроса: «Что сейчас у меня в рабочей области?»*

#### Поиск нужного узла

В Dynamo содержатся тысячи узлов, включая узлы из установленных пакетов. Следующие инструменты помогают Assistant выбрать правильный вариант, а не угадывать.

| Инструмент | Назначение |
| --- | --- |
| `get_nodes_info` | Поиск в библиотеке узлов, включая узлы пакета, и возврат точного узла для размещения. |
| `get_node_help` | Возврат справочной информации по узлу и пути к его образцу графа, если он существует. |
| `get_type_schema` | Возврат ожидаемого формата данных для типа Dynamo, например точка, число или цвет. |

*Пример запроса: «Какой узел использовать для получения площади поверхности?»*

#### Создание и редактирование графа

Следующие инструменты выполняют всю работу в рабочей области.

| Инструмент | Назначение |
| --- | --- |
| `create_nodes` | Размещение одного или нескольких узлов в рабочей области с необязательными начальными значениями. |
| `set_node_value` | Задание значений узлов ввода, таких как Number, String, Code Block и раскрывающиеся списки. |
| `connect_nodes` | Соединение порта вывода с портом ввода. |
| `disconnect_nodes` | Удаление проводов между двумя узлами. |
| `delete_node` | Удаление узла из рабочей области. |
| `rename_node` | Переименование узлов ввода и Watch, чтобы было понятно их назначение. Узлы функций сохраняют свои исходные имена. |
| `select_nodes` | Выбор узлов в рабочей области, чтобы можно было увидеть, какие из них имеет в виду Assistant. |
| `set_node_property` | Включение или отключение параметров узла: предварительный просмотр, замораживание, закрепленный предварительный просмотр, метки, а также ввод или вывод. |
| `set_node_lacing` | Задание для переплетения значения «Авто», «Кратчайший», «Самый длинный» или «Векторное произведение». |
| `set_node_port_list_at_level` | Задание уровня списка для порта ввода. |

*Пример запроса: «Добавь number slider и подключи его к входному параметру радиуса окружности».*

#### Организация и документирование графа

Рабочий граф не всегда легко читать. Следующие инструменты управляют компоновкой, группировкой, цветами и примечаниями.

| Инструмент | Назначение |
| --- | --- |
| `create_group` | Размещение группы вокруг набора узлов. |
| `create_groups` | Создание нескольких групп за одно действие. |
| `ungroup_by_guid` | Удаление группы. Входящие в ее состав узлы остаются в рабочей области. |
| `ungroup_by_title` | Удаление групп по названию. Входящие в их состав узлы остаются в рабочей области. |
| `get_available_group_styles` | Список стилей групп, которые можно использовать, включая пользовательские стили из пользовательских настроек. |
| `assign_group_styles` | Применение стилей групп, таких как «Входные данные», «Действия», «Выходные данные» и «Проверка». |
| `get_notes` | Вывод списка примечаний в графе. |
| `create_notes` | Добавление примечаний, поясняющих элементы графа. |
| `update_notes` | Редактирование текста примечания или его перемещение. |
| `delete_notes` | Удаление примечаний. |
| `set_note_state` | Прикрепление примечания к узлу таким образом, чтобы они перемещались вместе, или открепление примечания. |
| `auto_layout_workspace` | Переупорядочивание узлов с помощью встроенной автоматической компоновки Dynamo. |
| `set_workspace_description` | Запись описания графа в свойства файла. |

*Пример запроса: «Сгруппируй и выдели цветом входные данные, действия и выходные данные в этом графе, а затем добавь короткие примечания».*

#### Запуск графа и проверка результатов

| Инструмент | Назначение |
| --- | --- |
| `run_workspace` | Запуск текущего графа. В автоматическом режиме граф уже перезапускается при каждом изменении, поэтому этот шаг пропускается. |
| `get_workspace_warnings` | Вывод узлов с предупреждениями или ошибками, текста сообщения и рекомендуемых дальнейших действий. Сначала требуется запустить граф. |
| `get_node_output_values_shapes` | Вывод сводки выходных значений одного узла или каждого узла на графе. |
| `get_node_output_value` | Считывание всех выходных данных одного узла, по одной странице за раз, для результатов, размер которых слишком велик для отображения сводки. |

*Пример запроса: «Запусти граф и сообщи, почему узел List.GetItemAtIndex отображает предупреждение».*

#### Работа с файлами графов

Assistant также может работать с графами на диске, а не только с тем, который вы открыли.

| Инструмент | Назначение |
| --- | --- |
| `new_workspace` | Открытие нового пустого графа. Если текущий граф содержит несохраненные изменения, сначала появится запрос на их сохранение или отмену. |
| `save_workspace` | Сохранение текущего графа. По умолчанию он сохраняется в папке Dynamo «Документы». |
| `edit_graph_from_path` | Открытие сохраненного графа для редактирования без запуска. |
| `insert_graph_from_path` | Вставка сохраненного графа в текущую рабочую область. Так внедряются примеры узлов графов. |
| `run_graph_from_path` | Запуск сохраненного графа с необязательными входными значениями, которые вы предоставляете. |
| `run_graph_from_json` | Запуск графа из формата Dynamo JSON, без файла на диске. |
| `get_graph_info_from_path` | Считывание входных и выходных данных, а также метаданных сохраненного графа без его открытия. |
| `get_graph_info_from_json` | Считывание тех же сведений из графа, который предоставлен в формате Dynamo JSON. |
| `get_graphs_info_from_path` | Сканирование папки с графами и отображение информации о содержимом каждого из них. |
| `get_available_graphs_folders` | Вывод списка известных Dynamo папок, которые могут содержать графы. |

*Пример запроса: «Просмотри папку графов Dynamo и сообщи, на каких графах размещаются стены».*

{% hint style="warning" %}
Assistant может изменить граф. Сохраните результаты работы перед запросом на крупное редактирование и просмотрите результат перед сохранением существующего файла.
{% endhint %}
