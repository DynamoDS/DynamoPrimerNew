# RevitMCP и DynamoMCP

Autodesk Assistant получает возможности от серверов MCP. Каждый сервер предоставляет Assistant набор инструментов, и каждый инструмент выполняет одну задачу в программе, к которой он относится.

При работе в Revit важны два сервера: **RevitMCP** и **DynamoMCP**. Это не конкурирующие варианты, и вы не выбираете между ними. Они работают на разных уровнях, и Assistant использует тот, который соответствует вашему запросу.

### RevitMCP: непосредственные операции с моделью

RevitMCP, поставляемый как [Общедоступный сервер MCP Revit](https://help.autodesk.com/cloudhelp/2027/RUS/Revit-WhatsNew/files/GUID-97697CBF-0E11-484E-96E5-4277E3E8D61F.htm), включает в себя тщательно отобранный набор операций API Revit в качестве инструментов MCP. Каждый инструмент сопоставляется с определенной операцией в модели: поиск элементов, проверка параметров и количества, групповое редактирование параметров и создание снимков видов.

Это кратчайший путь для задачи, уже покрываемой набором инструментов. Один запрос становится одним вызовом, и модель немедленно изменяется. Не строится никакой граф и впоследствии ничего не запускается.

### DynamoMCP: инструменты для построения операции

DynamoMCP работает на один уровень выше. Инструменты этого сервера не выполняют непосредственно операции моделирования. Вместо этого они разрабатывают граф Dynamo: размещают узлы, соединяют их друг с другом, задают значения и запускают результат. Полный список инструментов см. в разделе [Сервер MCP Dynamo](../12-2_dynamo-mcp/1-what-is-dynamo-mcp.md).

Это важно из-за того, что представляет собой узел. Каждый узел в библиотеке Dynamo сам по себе является одним или несколькими вызовами API, которые уже написаны, протестированы и задокументированы. Узлы пакета и узлы Python доступны одинаково. Таким образом, небольшой набор инструментов для создания графов охватывает всю библиотеку Dynamo.

В результате инструменты DynamoMCP создают новые возможности, а не только используют существующие. Вместо фиксированного списка действий Assistant собирает запрошенное действие из узлов. На практике инструменты MCP, которые пишут графы, работают как инструменты, создающие другие инструменты.

### Разница на практике

Допустим, вы просите разместить марки дверей на одном уровне.

- Работа выполняется путем прямого вызова, который обрабатывается RevitMCP, и марки отображаются.
- С помощью DynamoMCP Assistant размещает узлы, собирающие двери, фильтрует их по указанному уровню, создает марки, а затем запускает граф.

Оба варианта приводят к маркировке дверей. Второй вариант также оставляет что-то на рабочей области.

| | RevitMCP | DynamoMCP |
| --- | --- | --- |
| Действие инструмента | Выполнение определенной операции Revit | Построение и запуск графа Dynamo |
| Зона доступа | Операции, включенные в набор инструментов | Любой узел в библиотеке, включая узлы пакета и узлы Python |
| Результат | Изменение модели | Изменение модели и графа, который его внес |
| Оптимально для | Однократная четко определенная задача | Логика, которую требуется проверить, настроить, использовать повторно или совместно |

### Преимущества графа

Граф — это запись работы, а не только ее результат. Как только он появляется в рабочей области, вы можете:

- Читать его и просматривать, что именно было сделано.
- Менять значение и выполнять его снова, не запрашивая всю задачу повторно.
- Сохранять его, чтобы запускать в другом проекте или передавать коллегам.
- Публиковать его в проигрывателе Dynamo, чтобы пользователи, не использующие Dynamo, могли его запускать.

Первый запрос выполняется дольше всего. Каждый последующий запуск почти не требует ресурсов.

{% hint style="info" %}
В Dynamo Sandbox инструмент Assistant обращается только к DynamoMCP, так как модель Revit для работы отсутствует. В Revit доступны оба варианта.
{% endhint %}

### Построение запроса

Не требуется указывать сервер в запросе. Достаточно описать результат, и Assistant выберет инструменты.

Если вам нужен именно граф, скажите об этом. Например, получив запрос *«Построй граф, который маркирует двери на уровне 2»*, Assistant поймет, что требуется многоразовая версия, а не просто промаркированные двери.
